## Resolver architecture and Instagram boundary

- VESPER keeps provider parsing in small adapters and shares HTML scanning, redirect validation, candidate probing, manifest parsing, planning and transfer validation. This is a good boundary for site churn; current remaining provider gaps include Instagram page metadata and live verification of YouTube Mix paging.
- The current upstream yt-dlp Instagram extractor has more provider-specific strategies, including direct media-version lists, carousel enumeration and GraphQL parsing ([source](https://raw.githubusercontent.com/yt-dlp/yt-dlp/master/yt_dlp/extractor/instagram.py)). Its interface and runtime dependencies are not a fit for VESPER, so the implementation here uses browser-observed whole-object URLs with a scoped picker instead of porting that machinery.
- The current upstream yt-dlp inline playlist implementation follows YouTube's `/next` endpoint with the Mix playlist id and the last panel item's watch endpoint ([source](https://raw.githubusercontent.com/yt-dlp/yt-dlp/master/yt_dlp/extractor/youtube/_tab.py#L3556-L3611)). VESPER now uses that bounded strategy for a deduplicated Mix snapshot, keeps the collection marked dynamic/incomplete, and preserves the first page when continuation fails. Validation is fixture-based; no live Mix request was made.
- Meta documents oEmbed as returning HTML for embedding, while its IG Media API requires an Instagram/Facebook user access token and is limited to professional accounts; `media_url` can be omitted for copyright-restricted content ([oEmbed reference](https://developers.facebook.com/docs/graph-api/reference/instagram-oembed/), [IG Media reference](https://developers.facebook.com/docs/instagram-platform/reference/instagram-media/v21.0/)). Recent upstream reports also show story retrieval returning login-required responses, even in cookie-enabled runs ([upstream issue](https://github.com/yt-dlp/yt-dlp/issues/17755)). VESPER therefore reports unavailable/auth-gated content and waits for the authorized browser observation path; it does not call Meta APIs or emulate site requests.

## Additional reliability work

- Unknown-length bodies now get a one-byte range probe when the source advertises ranges. A source that reports remaining bytes after a clean early close stays unpublished. Close-delimited bodies with no framing or range proof stay in the partial file with a useful NeedsAttention reason; well-framed chunked and HTTP/2 responses remain usable.
- HTML error pages are detected from response headers and the first body bytes, including `text/html` attachments and mislabelled archive downloads. The partial file is kept and an HTML response is never published as the requested media file.
- TikTok now parses universal, SIGI and `__NEXT_DATA__` player layouts and reports private/login and region statuses with typed errors. The existing signed-address parsing and mirror handling remain.
- Refreshed HTTP and live-HLS media sources can carry validated Cookie/Authorization headers to the exact replacement origin. Credentials stay in memory and are applied only after the replacement passes identity checks; a 401/403/407 now explains the likely recovery step.
- Automatic Chrome handoff retries temporary native-host errors without changing the Chrome download owner or transfer identity. Unconfirmed signed URLs are kept in bounded session storage. SameSite fallback now withholds cookies unless host and scheme match exactly.
- Optional “Prepare video formats in advance” is off by default. It makes metadata-only requests for visible non-DRM players, keeps results in a bounded 30-second memory cache, cools down repeated work per tab and clears results when the page changes.
- The Rescue window now offers manual refresh for an active live-HLS recording and checks the next playlist sequence before resuming it. The prefetch preference lives in the extension because the browser owns the page/player and the work; there is no duplicate desktop toggle without a supported settings-sync channel.
- Instagram blob players can now present direct or manifest URLs observed on the active frame/document within 15 seconds before or after player metadata. When multiple sources match, the picker requires a user choice and shows type/size hints without exposing signed query strings. It excludes partial 206 ranges unless headers show the full object. The response body is still fetched and verified by VESPER. Observed signed URLs are pruned from session storage after 10 minutes; the cache is capped at 25 sources per tab and 200 total across tabs. A response still cannot be tied to one exact video element when several players share a frame, so a coincident ad within the window remains ambiguous. This remains a public/browser-observed path; it does not add an unofficial API or a story/authentication bypass. [Meta's Instagram oEmbed API returns embed HTML](https://developers.facebook.com/docs/graph-api/reference/instagram-oembed/); the [Instagram Media API requires a user access token and may omit `media_url` for copyright-restricted content](https://developers.facebook.com/docs/instagram-platform/reference/instagram-media/v21.0/).
- The in-page picker now constrains flex children, clamps long titles and hides horizontal overflow; format labels and output controls can wrap within narrow viewports. Static CSS regression coverage passes; visual Chrome/DPI/accessibility review is still pending.
- Destination paths now expand environment variables and normalize once at the path-safety boundary. Settings loads and saves the normalized default; Add Download, quick download and batch review submit the resolved path, while engine options use the same normalized value. File details show the resolved absolute path instead of a literal `%USERPROFILE%` token. Regression tests cover expansion, display, parent-segment rejection and settings reload.
- Media conversion now remuxes compatible AAC-only MP4 sources to M4A and H.264/AAC MP4 sources to MP4 without opening Media Foundation. WAV and incompatible codecs still use the converter; regression fixtures compare copied AAC/H.264 samples and a Windows Media Foundation test decodes AAC to PCM WAV. No speed-up is claimed without a comparative timing run.

## Compatibility and operational limits

No runtime dependency, language, alternate UI framework or database migration was added to VESPER. Native SQLite and durability/publication contracts remain. Enum output values were appended, not renumbered. New bridge fields are optional; an old extension will not gain the new controls. Use the matching 1.0.2 app/extension for integration.

Secrets are absent from plans, recovery manifests, test fixtures, delivery reports and archives. A private transfer that loses its in-memory context on restart must re-authorize/re-resolve rather than replay credentials to another host. Authenticated merge/DASH contexts unsupported by the existing engine are still rejected rather than silently discarded. Do not use the live example's expiring URL as a fixture.

The workspace preview is only a read-only file explorer over real source and deliverables. It is not part of VESPER, not in its patch, and introduces no Next.js/PostgreSQL dependency into the Windows application.
