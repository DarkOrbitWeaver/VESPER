# Luna: practical Windows integration handoff

1. Save a clean checkout at `2620e76e0fa987e93189646ae6442cd0005fba7c`. Keep existing downloads/data backed up. Do not apply VESPER-FULL.patch or PHASE-01 in addition to this consolidated patch.
2. Verify SHA256SUMS.txt. Run `git apply --check VESPER-consolidated.patch`, then `git apply --index --binary VESPER-consolidated.patch` from the repository root. See BASELINE.json for the independently checked resulting tree. No push is required.
3. With Windows .NET 10 SDK: `dotnet build VESPER.slnx -c Release --nologo`. Run `scripts/Run-Tests.ps1` (or the engine, resolver, Windows/Setup projects and `node --test tests/extension/*.test.mjs`). The known resolver merge-warning regression is fixed; do not suppress test failures. Cross-compilation here is not a Windows result.
4. Package locally with `scripts/Build-Release.ps1 -AllowUnsigned` for a development VM. A distributable release requires a certificate in the Windows store, `signtool.exe` on PATH, and VESPER_SIGN_CERT_SHA1 (or -SigningCertificateThumbprint). Signing happens before payload hashing; failures must stop packaging. Store publication still needs the owner's listing. Do not present unsigned/unpacked builds as approved releases.
5. Verify Settings -> Browser says 1.0.2, helper registration points at this build, and the matching extension says 1.0.2. Portable Connect Chrome asks for consent. Disconnect must not remove another copy's registration. Manually check updates once; no idle network traffic should result. GitHub may legitimately have no public release.
6. Paste the supplied TikTok watch URL directly with the extension disabled. Expect real formats and an MP4; inspect AAC audio and 1080x1920 HEVC (or the currently offered equivalent), play/seek with a supported player. The native Linux path passed for a 400,577-byte file, not a permanent upstream guarantee. On 403, re-resolve the page; inspect credential presence and origin only, never log cookie values or signed queries. Repeat from the butterfly, context menu and browser sign-in toggle. Chrome UI is unverified here.
7. In the browser picker exercise ordinary Download/Queue, output changes, collapse/expand, track choice, subtitle sidecars and ranges. These previously had runtime initialization/scope defects. Subtitle jobs must not carry the media Cookie header. Test frame-scoped sign-in/CHIPS in an authorized embed; unknown-frame automatic captures must stay conservative.
8. Smart Select: open from a normal webpage context menu, filter/check reusable links, dynamically add a file link/button data-url, then Review in VESPER. Uncheck one, choose a folder, queue/download. Only selected items should submit. Test URL-less POST/blob/single-use buttons by clicking the real page button: Chrome must retain ownership when replay is unsafe, including completed files. Kill/restart the MV3 worker during a staged handoff and confirm recovery.
9. Rendering: scroll/hover 40+ grid rows; switch Settings pages with About visible; open long audio/subtitle menus; test 100/125/150/200% DPI, 150% text and high contrast. Check butterfly scroll/fullscreen/reduced motion and keyboard/Narrator. None of these were visually run here.
10. Conversion: confirm native AAC M4A uses copy; Opus output opens as Ogg Opus with title/artist/cover; WAV decode actually works with the installed MF codecs and a .125-.625 s clip has exactly the requested sample count. WAV currently fetches/decodes the entire source, has RIFF limits and no embedded cover. Verify MP4/M4A metadata and A/V sync, cancellation, crash recovery and free-space failure. Do not claim hardware speed-up until measuring the target machine; enable-hardware is not proof of GPU use.
11. Transfers: compare ordinary downloads and HLS/DASH VOD on representative storage/network, including pause/cancel during prefetch, a saturated host, IPv6 failure, retries and recovery. Never disable flush-before-commit or output validation for a benchmark. Discontinuity epochs, embedded subtitles, indexed clipping and MP3/FLAC encoders remain open; expected safe refusal is not completed support.
12. Installer: close VESPER before install/upgrade/repair/uninstall (current mutex guard requires it), test a clean VM and rollback. Downloads/settings/history must remain. Optional data deletion and graceful setup exit signaling are not implemented. Report these as open, not verified. Keep actual outcomes in STATUS.tsv.

Troubleshooting evidence to keep: app/extension versions, public page URL, job reason/status, codec/container, whether credentials were present and which origin was permitted, Windows/driver/codec-extension versions. Never include cookies, Authorization, signed query strings, native user databases or real downloaded media in a shared report.
