# Media support

Site compatibility and available Windows codecs vary by device and source.

- VESPER saves direct HTTP/HTTPS files, completed HLS, and supported clear DASH plans. It can merge compatible tracks into MP4, M4A, WebM, or Matroska without re-encoding them, including supported HLS video with separate packed AAC audio. Live HLS recording requires one usable rendition with audio included. HLS changes in codec or program layout can be refused to protect output integrity.
- Compatible MP4 and M4A can re-encode eligible sources using Windows Media Foundation. M4A prefers copying compatible AAC. MP3 conversion requires a confirmed Windows encoder and a supported source track. WAV uses a supported decoder and can write RF64. Opus copies supported existing Opus packets. FLAC files can be saved in their source format. FLAC encoding remains open. Some sites offer only a combined video-and-audio stream, for which the picker can decline audio extraction.
- Completed HLS/DASH trim fetches the needed segments and cuts at their boundaries. Supported H.264/AAC MP4 clips from direct sources download the full source, then copy the selected video and audio without re-encoding. WAV trim downloads and decodes the full source before saving the selected samples. Indexed MP4 and WebM clipping remains open.
- Tags, cover art, and chapters depend on the selected output and source metadata. Supported SRT/WebVTT tracks can be embedded in eligible MP4/Matroska outputs. Other supported captions are saved separately. Segmented and live captions have additional limits.
- Media discovery needs an accessible file or supported stream. VESPER can read the track table near the start of a direct MP4 to identify its resolution, codecs, and audio tracks. If the table is unavailable, some details stay unconfirmed. VESPER respects DRM and site access controls.
- When a player leaves several possible sources, VESPER checks a few and shows the available duration and format details. Choose the source that matches the video. Some requests are invisible to the Chrome extension.
- Early capture can prevent Chrome download creation for verified direct links and explicitly named same-origin exports, including supported query-based URLs. Supported page-created Blob files can use the browser-body bridge. Fresh handoffs require verified identity and readiness; Chrome retains ownership when safe replay or native acceptance cannot be established. Opaque signed URLs, POST responses and worker-owned blobs are not universally captured. Approved same-origin sign-in credentials are scoped to the permitted origin and never forwarded through a credentialed redirect.
- Copied MP4, WebM and MPEG-TS samples can inform player/source association without retaining media payloads. Independently witnessed byte-addressed MP4 slices may suggest a full resource, but only matching range headers, length and validators permit a native probe; the derived resource requires explicit selection. This is not arbitrary fragment reconstruction.
- Compatible HTTP, HLS and DASH delivery changes can retain independently verified completed bytes. Direct audio/video track work is interleaved and bounded. HTTP/2 stream admission is experimental; production transport remains unchanged until real TLS, proxy and throughput qualification.
- Native remux copies existing audio and video. Changing codecs requires decoding and encoding, which can take longer.
